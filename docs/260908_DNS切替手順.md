# DNS切替手順（laplust.com → Netlify）

現行のStudioサイトから新サイト（Netlify）へ、laplust.com の向き先を切り替える手順。
DNSゾーンはさくらインターネットのネームサーバ（ns1/ns2.dns.ne.jp）で管理されている。

## 現状のDNSレコード（2026-09-08 実測）

| 名前 | タイプ | 値 | TTL | 切替時の扱い |
| --- | --- | --- | --- | --- |
| laplust.com | A | 34.111.141.225（Studio） | 3600 | **→ 75.2.60.5（Netlify）へ差し替え** |
| www | CNAME | laplust.com | 3600 | そのまま（apexに追従するため変更不要） |
| laplust.com | MX | 1 smtp.google.com | 3600 | **絶対に触らない**（Google Workspaceメール） |
| laplust.com | TXT | v=spf1 include:_spf.google.com ~all | 3600 | 触らない（メール送信認証） |
| laplust.com | TXT | google-site-verification=... | 3600 | 触らない（Search Console検証済みの証跡） |

変更するのは **Aレコード1件のみ**。メール・SPF・サイト検証には一切影響しない。

## 役割分担

- **お客様**: Netlifyダッシュボードとさくら会員メニューでの操作（画面操作が必要なため）
- **Claude**: 切替直前の記事最終同期、切替後の検証（全ページ・リダイレクト・フォーム・GA4）、
  値や状態の確認はすべてこちらで実施

## 手順

### 事前準備（切替の前日まで・任意だが推奨）

1. さくら会員メニュー（ https://secure.sakura.ad.jp/ ）→ 契約情報 → ドメインの確認 →
   laplust.com の「ゾーン編集」を開く
2. laplust.com のAレコードの **TTLを 3600 → 300 に変更**して保存
   （切替の反映とロールバックを速くするため。TTL欄が編集できないUIの場合はスキップ可）

### 切替当日 ①: 記事の最終同期（Claude）

- 現行Studioサイトに9/1以降に公開された新着記事がないか確認し、あれば取り込んでmainへ反映
- 「切替を実施します」の連絡をもらった時点でこちらで実施する

### 切替当日 ②: Netlifyにカスタムドメインを追加（お客様・5分）

1. Netlifyダッシュボード → 対象サイト → **Domain management**
2. 「Add a domain」→ `laplust.com` を入力して追加
   （「already registered」等の確認が出たら「Add domain」で続行）
3. 同様に `www.laplust.com` も追加（またはlaplust.com追加時に自動でエイリアス追加される）
4. **Primary domain が laplust.com** になっていることを確認
   （wwwが主になっていたら「Options」→「Set as primary domain」で入れ替え）
5. この時点でNetlifyに「Check DNS configuration」等の警告が出るのは正常
   （DNSがまだStudioを向いているため。次のステップで解消する）

### 切替当日 ③: さくらでAレコードを差し替え（お客様・5分）

1. さくら会員メニュー → laplust.com の「ゾーン編集」
2. **エントリ名「@」（または空欄）・タイプ A・値 34.111.141.225** のレコードを編集し、
   値を **`75.2.60.5`** に変更（Netlifyのロードバランサ）
3. 保存（「データ送信」等の確定ボタンまで押す）
4. **他のレコード（MX・TXT・www）は変更しない**

### 切替当日 ④: 反映とSSL証明書の確認（Claude＋お客様）

1. DNS伝播の確認（Claudeが実施）: laplust.com のAが 75.2.60.5 を返すこと
   （TTL短縮済みなら数分〜、未実施なら最大1時間程度）
2. NetlifyのDomain management画面で警告が消え、
   **HTTPS → 「Let's Encrypt certificate」が自動発行**されることを確認（通常数分。
   「Verify DNS configuration」ボタンが出ていたら押す）
3. 証明書発行後、https://laplust.com が新サイトを表示することを確認

### 切替当日 ⑤: 総合検証（Claude）

- 全主要ページの表示・アセット配信（404ゼロ）
- 旧URL61件超の301リダイレクト（大文字→小文字）
- www.laplust.com → laplust.com への転送
- フォーム送信（テスト送信→シート記録・通知・自動返信）
- GA4リアルタイムレポートに計測が乗ること（本番ドメイン限定ガードの解除確認）
- sitemap.xml / robots.txt の配信

### 切替後（当日〜翌日）

1. **Search Console**: プロパティ（DNS TXTで検証済み）でサイトマップ
   `https://laplust.com/sitemap.xml` を送信
2. 数日間、表示・問い合わせ・検索流入を監視（Looker Studioダッシュボード）
3. TTLを300に下げていた場合は3600へ戻す（任意）

### 安定確認後（数日〜数週間後）

- **Studio解約**（アセットは退避済みのため技術的リスクなし。これが最後の工程）

## ロールバック（問題発生時）

さくらのゾーン編集で laplust.com のAレコードを **34.111.141.225** に戻すだけで
旧Studioサイトに復帰する（TTL 300なら数分で反映）。Studio解約前であれば
いつでも巻き戻せるため、解約は十分な安定確認後に行うこと。

## 注意事項

- 切替はメール（MX/SPF）に一切影響しない構成だが、ゾーン編集画面では
  対象レコード以外を誤って変更・削除しないこと
- 実施は平日午前など、問題発生時にすぐ対応できる時間帯を推奨
