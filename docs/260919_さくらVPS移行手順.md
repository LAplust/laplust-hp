# さくらVPS移行手順（Netlify → さくらVPS）

背景: 2026-09-19、Netlify無料枠の帯域上限到達によりサイトが一時停止。
動画の720p圧縮（117MB→21MB）と併せ、帯域制限のないさくらVPSへ移行する。
DNSゾーンはさくらのまま動かさず、**変更はAレコード1件のみ**。

## 構成

```
GitHub main へ push
  → GitHub Actions（.github/workflows/deploy.yml）が自動ビルド
  → rsync で VPS の /var/www/laplust/ へ同期
  → nginx が https://laplust.com として配信（SSLはLet's Encrypt自動更新）
```

- nginx設定: `infra/nginx/laplust.conf`（本体）と `infra/nginx/redirect-map.conf`（旧URL64件の301）
- 記事公開などの運用フローは従来と完全に同じ（mainマージ＝本番反映）

## 事前確認（VPSの状態）

対象VPS（既存: 153.126.202.107 / Ubuntu想定）にSSH接続し、以下を確認:

```bash
# 何が動いているか（旧WordPress時代のdockerが残っている可能性）
docker ps 2>/dev/null
sudo ss -tlnp | grep -E ':80|:443'
lsb_release -a
```

- **80/443番ポートを旧コンテナ等が使用している場合は停止**してから進める:
  `docker stop <コンテナ名>`（自動起動も無効化: `docker update --restart=no <コンテナ名>`）

## セットアップ（VPS上で1回だけ・約20分）

```bash
# 1) nginxとcertbotのインストール
sudo apt update
sudo apt install -y nginx certbot python3-certbot-nginx rsync

# 2) 配信ディレクトリ（デプロイユーザーが書き込めるように）
sudo mkdir -p /var/www/laplust /var/www/certbot
sudo chown -R $USER:$USER /var/www/laplust

# 3) リポジトリのnginx設定を配置
#    （ローカルPCから）
scp infra/nginx/redirect-map.conf <user>@<VPS>:/tmp/
scp infra/nginx/laplust.conf <user>@<VPS>:/tmp/
#    （VPS上で）
sudo mv /tmp/redirect-map.conf /etc/nginx/conf.d/
sudo mv /tmp/laplust.conf /etc/nginx/sites-available/
sudo ln -sf /etc/nginx/sites-available/laplust.conf /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default

# 4) SSL証明書の取得はDNS切替後に行うため、まずSSL部分を無効化した状態で疎通確認
#    laplust.conf の 443 の2つの server ブロックを一時的にコメントアウトして:
sudo nginx -t && sudo systemctl reload nginx

# 5) ファイアウォール（ufw使用時）
sudo ufw allow 'Nginx Full'
```

## デプロイ用SSH鍵とGitHub Secrets

```bash
# VPS上でデプロイ専用鍵を作成
ssh-keygen -t ed25519 -f ~/.ssh/deploy_key -N "" -C "github-actions-deploy"
cat ~/.ssh/deploy_key.pub >> ~/.ssh/authorized_keys
cat ~/.ssh/deploy_key   # ← この秘密鍵をGitHub Secretsへ
```

GitHubリポジトリ → Settings → Secrets and variables → Actions → New repository secret:

| Secret名 | 値 |
| --- | --- |
| `VPS_HOST` | VPSのIPアドレス |
| `VPS_USER` | SSHユーザー名 |
| `VPS_SSH_KEY` | 上記 `deploy_key` の中身（秘密鍵全文） |

登録後、Actionsタブから「Deploy to Sakura VPS」を手動実行（workflow_dispatch）し、
`/var/www/laplust/index.html` が同期されることを確認。

## 切替（DNS変更 → SSL取得）

1. **動作確認**: `curl -H "Host: laplust.com" http://<VPSのIP>/` でトップページHTMLが返ること
2. **さくらのゾーン編集**: laplust.com の Aレコードを `75.2.60.5` → **VPSのIPアドレス** に変更
   （MX・TXT・wwwは触らない。ロールバックはこの値を戻すだけ）
3. DNS伝播後（TTL 3600のため最大1時間）、**SSL証明書を取得**:
   ```bash
   sudo certbot --nginx -d laplust.com -d www.laplust.com \
     --non-interactive --agree-tos -m info@laplust.com --redirect
   ```
   ※laplust.conf の443ブロックをコメントアウトしていた場合は、certbot実行前に戻して
   `sudo nginx -t` が通ることを確認（証明書パスはcertbotが自動設定/確認する）
4. 自動更新の確認: `sudo certbot renew --dry-run`

## 切替後の検証（Claude実施）

- 主要ページ200・アセット404ゼロ・大文字URL301・www→apex・末尾スラッシュ301
- キャッシュヘッダ（/assets/* が immutable）
- フォーム送信（honeypot）・GA4発火
- GitHub Actionsデプロイの成功（main pushで反映されること）

## Netlify側の後始末（安定確認後）

- Netlifyのサイトからカスタムドメイン laplust.com / www を削除（他所での再利用ブロック回避）
- しばらく残す場合も課金は発生しない（Freeプランのまま放置可）

## 運用上の注意

- 記事の追加・修正はこれまでどおり main マージで自動反映（GitHub Actions経由）
- `site/public/_redirects` に新しいリダイレクトを足した場合は
  `infra/nginx/redirect-map.conf` にも同じ行を追加してVPSへ再配置すること
- OSのセキュリティ更新: `sudo apt install unattended-upgrades` で自動化を推奨
- 証明書はcertbotのsystemdタイマーで自動更新される（要 `certbot renew --dry-run` での確認）
