# サイト死活監視の設定（Slack＋メール通知）

作成日: 2026年9月20日

GitHub Actions（`.github/workflows/uptime.yml`）が https://laplust.com/ を
**約5分間隔**（GitHubのスケジューラ都合で実際は5〜15分）で外形監視する。

## 動作

| 状況 | 動作 |
| --- | --- |
| ダウン検知（3回リトライ後もHTTP 200以外） | `site-down`ラベルのIssueを起票＋**Slack通知＋メール通知**（一次対応手順つき） |
| ダウン継続中 | 追加通知なし（Issueが開いている間は通知を繰り返さない） |
| 復旧検知（HTTP 200に戻る） | Issueを自動クローズ＋**復旧をSlack・メールで通知** |

通知先Secretsが未設定でも監視とIssue起票は動く（通知だけスキップされる）。

## 初期設定（1回だけ・約10分）

### 1. Slack Incoming Webhookの作成

1. https://api.slack.com/apps → 「Create New App」→「From scratch」
   （アプリ名例: `サイト死活監視`、ワークスペースを選択）
2. 左メニュー「Incoming Webhooks」→ Activate をOnに
3. 「Add New Webhook to Workspace」→ 通知先チャンネルを選択して許可
4. 発行された `https://hooks.slack.com/services/...` のURLをコピー

### 2. Gmailアプリパスワードの作成（メール通知の送信元）

1. 送信元にするGoogleアカウント（例: info@laplust.com）で
   https://myaccount.google.com/apppasswords を開く
   （**2段階認証が有効であることが前提**。無効の場合は先に有効化する）
2. アプリ名（例: `uptime-monitor`）を入れて生成 → 16桁のパスワードをコピー
   （通常のログインパスワードではないので注意）

### 3. GitHub Secretsへの登録

https://github.com/LAplust/laplust-hp/settings/secrets/actions → New repository secret:

| Secret名 | 値 |
| --- | --- |
| `SLACK_WEBHOOK_URL` | 手順1のWebhook URL |
| `MAIL_USERNAME` | 送信元Gmailアドレス（例: info@laplust.com） |
| `MAIL_APP_PASSWORD` | 手順2の16桁アプリパスワード |

メールの宛先は `info@laplust.com` 固定（変更する場合は uptime.yml の `to:` を編集）。

## 通知テスト

1. Actionsタブ → 「Uptime Monitor」→「Run workflow」
2. `url` に存在しないURL（例: `https://laplust.com/zzz-test`）を入れて実行
   → 障害Issueが起票され、Slackとメールに🚨通知が届くことを確認
3. もう一度「Run workflow」を**URL欄を初期値のまま**実行
   → Issueが自動クローズされ、✅復旧通知が届くことを確認

## 運用上の注意

- **GitHubの仕様**: リポジトリに60日間コミットがないとスケジュール実行が自動停止する
  （停止前にGitHubから警告メールが届く。Actionsタブの当該ワークフローで再有効化できる）
- 監視間隔は cron 上は5分だが、GitHubの混雑により5〜15分程度になる。
  より厳密な監視が必要になった場合は外部監視サービス（UptimeRobot等）の併用を検討
- GitHub自体の障害中は監視も止まる。バックアップとして、さくらVPSコントロールパネルの
  「サーバー監視」（メール通知のみ・GitHub非依存）を併用するとより堅牢
- 誤検知対策として3回リトライ（間隔30秒）後にのみダウン判定する
