# フォーム → Google Sheets 連携 導入手順

HPの3フォーム（お問い合わせ / LA-OCA無料申し込み / LA-Eye資料請求）の送信内容を
スプレッドシートに記録し、担当者へ通知メールを送るための手順。

方式は **GAS（Google Apps Script）のWebアプリ**。ホスティング環境（Netlify / さくらVPS）に
依存しないため、運用環境の決定前でも導入でき、環境を変えてもそのまま動く。

## 全体像

```
フォーム送信 → GAS WebアプリURL → スプレッドシートに1行追記 ＋ 通知メール
```

- シートのタブはフォームごとに自動作成される（手動でのタブ・ヘッダー作成は不要）
- スパム対策（honeypot）はGAS側で除外
- 記録される列: 受信日時 / 各入力項目 / 送信元ページ

## 手順（Google側の作業・約10分）

### 1. スプレッドシートを新規作成

1. [sheets.google.com](https://sheets.google.com) で空のスプレッドシートを作成
2. 名前を付ける（例: `HP問い合わせ管理`）

### 2. GASスクリプトを設置

1. スプレッドシートのメニュー「拡張機能」→「Apps Script」
2. 開いたエディタの `コード.gs` の中身を全部消し、
   リポジトリの `scripts/gas/form-receiver.gs` の内容を貼り付け
3. 冒頭の設定を確認・編集
   - `NOTIFY_EMAIL`: 通知先メールアドレス（初期値 info@laplust.com）
   - 通知不要なら `SEND_NOTIFICATION = false`
4. 保存（Ctrl+S）

### 3. Webアプリとしてデプロイ

1. エディタ右上「デプロイ」→「新しいデプロイ」
2. 歯車アイコン →「ウェブアプリ」を選択
3. 設定:
   - 説明: 任意（例: HPフォーム受信）
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**（←重要。サイト訪問者の送信を受けるため）
4. 「デプロイ」→ 初回はアクセス承認を求められるので、自分のアカウントで許可
   （「このアプリは確認されていません」と出たら「詳細」→「（安全でないページに）移動」で進む。
   自作スクリプトなので問題ない）
5. 表示される **WebアプリのURL**（`https://script.google.com/macros/s/…/exec`）をコピー

### 4. 共有するもの

- WebアプリのURL（上記）
- （NOTIFY_EMAILを手順2で変更済みなら不要）通知先メールアドレス

→ この2つを開発側（Claude）に共有すると、サイトの3フォームの送信先を
このURLに接続し、送信テストまで実施する。

## 運用中の環境（2026-09-03 導入済み）

- 記録先スプレッドシート: https://docs.google.com/spreadsheets/d/1TLdmXK5i2vTl4-qk8KKhKy03d8nRNFq8rUS9_i2rYeQ/edit
- WebアプリURL: サイト側 `site/lib/submitForm.ts` に設定済み

## 自動返信（訪問者宛て受付完了メール）

- 3フォームすべてで、送信された「メールアドレス」宛てに受付完了メールを自動送信する
- 差出人: `(自動返信)株式会社LAplust <info@laplust.com>`（Gmailのエイリアス送信を使用。
  実行アカウントのGmailで info@laplust.com が「他のメールアドレスから送信」に
  登録されていることが前提）
- 文面はフォームごとにスクリプト冒頭の `REPLY_TEMPLATES` で定義（編集後は再デプロイ）
- 自動返信が失敗しても受付・記録・担当者通知は成立する（通知メール内に
  「自動返信: 送信済み/失敗」のステータスが記載される）
- 送信上限: Google Workspaceは1日1,500通（無料Gmailは100通）

## 運用メモ

- **対応管理**: シートに「対応状況」などの列を右側に足して自由に使ってよい
  （追記は行単位なので、右側に列を足しても壊れない）
- **スクリプトの修正**（通知先変更など）: Apps Scriptエディタで編集後、
  「デプロイ」→「デプロイを管理」→ 鉛筆アイコン → バージョン「新バージョン」→「デプロイ」
  で反映（URLは変わらない）。「新しいデプロイ」で作り直すとURLが変わるので注意
- **迷惑メール対策**: honeypot（botが埋めがちな隠し入力欄）で機械的な送信を除外している。
  すり抜けが増えた場合はreCAPTCHA導入を別途検討

## セキュリティ上の注意

- WebアプリURLは公開ページのコードに含まれるが、できるのは「決められた形式の行追記」のみ。
  シートの閲覧・編集権限とは無関係（シート自体は共有設定した人しか見られない）
- スプレッドシートの共有は必要最小限のメンバーに留めること（問い合わせ内容は個人情報）

## 営業メール判定（2026-09-08追加）

人が手入力する営業投稿はhoneypotでは防げないため、キーワードのスコア方式で
自動判定する仕組みをスクリプトに追加した（旧サイトでは毎日10通程度が届いていた）。

### 動作

- 全入力項目のテキストを対象に、強シグナル（「突然のご連絡」「営業代行」等: 2点）と
  弱シグナル（「ご担当者様」「御社」等: 1点）を加点。種別「その他のお問合せ」は+1点
- 合計が `SALES_THRESHOLD`（既定: 3点）以上で「営業の可能性」と判定
- 判定されても**受付・シート記録・自動返信は通常どおり**行われる（誤判定で
  本物のお客様を取りこぼさないため）。変わるのは以下の2点のみ:
  - 担当者通知メールの件名の先頭に **【営業の可能性】** が付く（本文に検出語も記載）
  - シートの「営業判定」列に「営業の可能性（スコアN）」と記録される

### 受信トレイから営業通知を除けたい場合（Gmail側・任意）

Gmailの設定 → フィルタとブロック中のアドレス → 新しいフィルタを作成 →
件名: `【営業の可能性】` → 「受信トレイをスキップ」＋「ラベルを付ける（例: HP営業）」。
これで営業通知はラベルの中に溜まり、受信トレイには通常の問い合わせだけが届く。
※運用開始から1〜2週間は誤判定がないかラベル内を時々確認すること

### キーワード・しきい値の調整

- スクリプト冒頭の `SALES_KEYWORDS_STRONG` / `SALES_KEYWORDS_WEAK` / `SALES_THRESHOLD` を編集
- すり抜けた営業文があれば、その文の特徴的な言い回しをSTRONGに追加していくと精度が上がる
- 編集後は「デプロイ」→「デプロイを管理」→ 鉛筆 → 新バージョン → デプロイ（URL不変）
- 判定ロジックの動作確認は、エディタで `testSalesCheck` を実行して実行ログを見る

### 抑止文言

サイト側のお問い合わせフォーム（/contact・/la-eye/contact）に
「※営業・売り込みを目的としたお問い合わせはご遠慮ください。」を表示している。
